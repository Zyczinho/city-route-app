# Lisbon OSM snapshot — issue #148

This pilot uses a bounded OpenStreetMap/Overpass query over central Lisbon and nearby city districts, not a generic geocoder or invented seed data. **Source:** © OpenStreetMap contributors, licensed under ODbL 1.0. License: https://www.openstreetmap.org/copyright

The source of truth is the actual snapshot in `data/cities/lisbon/places.json`; each record preserves its node/way/relation ID and canonical URL. `import-report.json` preserves the endpoint, extraction time, Overpass dataset timestamp, bounding box, raw record count, SHA256 checksum and per-category counts. Files are generated by `scripts/import-lisbon-osm.mjs`, not hand-curated.

## Reproducible import

On the dedicated `work/lisbon-osm-148` branch, GitHub Actions runs the importer once on the workflow push, then `node scripts/generate-city-import.mjs lisbon 021`, then `npm test` and `npm run build`. The workflow commits the dataset and SQL to **that branch only**; never deploys or invokes hosted Supabase. If external Overpass services are unavailable, the job fails without creating fake records. The branch can be retried after external service recovery.

The importer limits the output to 100–200 real named POIs within Lisbon's radius. Selection uses category quotas, existing OSM metadata (website/Wikidata/opening hours), stable OSM IDs, proximity and duplicate-name checks. It is *not* a popularity or quality ranking. A site could be closed or relocated; a locally verified pilot should check the prominent places before promotion.

## Import limitations

- No ratings, review counts, tickets, commercial prices, photographs, editorial routes or real-time opening-hours verification.
- `cost: 0` is the schema's required numeric fallback and is **not evidence that a venue is free**; each OSM record has `metadata.costUnknown: true`. Route costs must not be advertised as reliable until planner handling is improved.
- OSM site tags may contain stale URLs or incorrect category assignments; defer confidence-sensitive marketing claims.
- OSM data should carry license notice when publicly displayed; map tile attribution already exists, but listing/derived-database attribution must be confirmed before public rollout.
- Set category-specific `minutes` as planning assumptions; they are not promises of actual opening hours or stay duration.
