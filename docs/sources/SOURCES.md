# Recommendation sources registry

Owned by the Source Scout (`.claude/agents/source-scout.md`). A source is used **inside City Route** only after Jakub changes its status to `approved`. No scraping, bulk collection, copied descriptions/reviews or unlicensed photos. A public page, open website or presence of dates does **not** create an API licence.

## Source selection rules (Warsaw pilot, 2026-11-06)

- `candidate` = evaluated research lead, **not** permission to import or display a derived feed. `approved (in use)` = previously authorized source/usage; do not extend permission to other datasets.
- **Link only** means editorial/manual discovery and a link to the **original** provider or event page. Any City Route listing must be separately checked against its primary organizer/venue and independently described. No automated copying of another site's curated list, text, photo, reviews or ticket data.
- For municipal/open datasets, check the **specific dataset's** licence, API authentication/limits, attribution, update timestamp and fields before proposing an integration card; the portal's general openness is not a grant over every resource.
- The “Today” column below is a **coverage signal observed on 2026-11-06**, not an authorization to ingest or a promise of continuous availability. Re-check date, timezone, cancellation, venue, price and official event URL before publication. Source update rhythms are proposed monitoring cadences, not proven API SLAs.
- Existing Ticketmaster integration is tracked separately; sources here aim to close the niche/nightlife/free-event coverage gap in #105.

Do not feed an automated third-party scraper into production. Date-specific sources should be revalidated at event level, with late cancellations and ticket changes expected.

## Permission and integration checklist for the next agent

1. Owner approval of a candidate **does not replace** publisher/API permission. Record the exact licensed rights (event names/dates versus descriptions/images), canonical source URL, attribution format, quotas, update schedule and whether commercial use is allowed.
2. Before opening an API integration PR, create an integration card under `docs/integrations/` and verify a **real** authorized endpoint and recent Warsaw events. Map provider IDs to deduplicate, preserve organizer URL and venue timezone (`Europe/Warsaw`), and don't fabricate sold-out state.
3. If no authorized feed exists, the candidate remains **manual curation + primary-source link** only. Do not turn that into a background scraping job.
4. Founder chooses sources to approve; integration and production publishing are separate work from this docs-only #114 PR.
